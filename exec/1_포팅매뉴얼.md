# 1. 포팅 매뉴얼 — 빌드 및 배포

## 0. 프로젝트 개요

Folio는 웹소설·시나리오 작가를 위한 원고 편집 서비스로, 데스크탑(Electron) + 웹 + 랜딩 페이지 + Spring Boot 백엔드 + FastAPI AI 서버로 구성된다.

```
S14P31F203/
├── frontend/   # Electron 데스크탑 + 웹 에디터 (코드 공유)
├── landing/    # 랜딩 페이지 (React + Vite, 별도 빌드)
├── backend/    # Spring Boot (Kotlin)
├── ai/         # FastAPI + Celery (Python)
├── infra/      # Docker / Nginx / 모니터링
└── docs/       # 설계 문서
```

배포 환경: AWS EC2 단일 서버 + Docker Compose + Nginx + Blue/Green 무중단 배포.

### 2.4 Infra / Docker Compose (`infra/{dev,test,prod}/.env`)

Doppler에서 다운로드하여 `.env`로 사용한다. Compose 의 `${VAR}` 치환에 사용되는 변수들이 모여 있다.

```bash
doppler secrets download --no-file --format env > .env
docker compose --env-file .env up -d
rm .env
```

## 3. 빌드 / 실행

### 3.1 소스 클론

```bash
git clone https://lab.ssafy.com/s14-final/S14P31F203.git
cd S14P31F203
```

### 3.2 Doppler 초기 세팅 (최초 1회)

```bash
doppler login
cd backend && doppler setup    # project: storyzip, config: dev
cd ../ai && doppler setup
cd ../frontend && doppler setup
cd ../infra/dev && doppler setup
```

### 3.3 인프라(Docker) 기동 — dev

```bash
cd infra/dev
doppler run -- docker compose -f docker-compose.dev.yml up -d
```

`postgresql:5432`, `redis:6379` 가 기동된다. (DDL은 컨테이너 최초 기동 시 자동 적용)

### 3.4 Backend 실행

```bash
cd backend
doppler run -- ./gradlew bootRun --args='--spring.profiles.active=dev'
# → http://localhost:8080
```

빌드 결과물: `backend/build/libs/folio-backend-*.jar`

### 3.5 AI Server 실행

```bash
cd ai
python -m venv venv
source venv/bin/activate         # Windows: venv\Scripts\activate
pip install -e ".[llm,db,dev]"
doppler run -- uvicorn app.main:app --reload --port 8000
# → http://localhost:8000

# Celery worker (별도 터미널)
doppler run -- celery -A app.celery_app worker --loglevel=info
```

### 3.6 Frontend 실행

```bash
cd frontend
pnpm install

# Electron 데스크탑 앱
doppler run -- pnpm dev

# 웹 에디터
doppler run -- pnpm dev:web
# → http://localhost:5173
```

### 3.7 Landing 페이지 실행

```bash
cd landing
pnpm install
pnpm dev
# → http://localhost:5174
```

### 3.8 Production 빌드 (Electron 배포)

```bash
cd frontend
export DOPPLER_TOKEN=$DOPPLER_TOKEN_PRD
doppler run --config prd -- pnpm make
# 결과물: frontend/out/make/ (Windows: *.exe / macOS: *.dmg)
```

## 4. 배포 (Production / EC2)

### 4.1 서버 사양 / 사전 설정

- AWS EC2 (Ubuntu 22.04 LTS, 권장 t3.large 이상)
- Docker / Docker Compose v2 설치
- 도메인 + Route53 A 레코드 → EC2 EIP
- 보안그룹: 80, 443, 22 인바운드

상세 절차는 [ec2-setup-guide.md](../docs/ec2-setup-guide.md).

### 4.2 Production Compose 구조

```
infra/prod/
├── docker-compose.yml         # 공유 (Nginx, PG, Redis, Mongo, PowerSync, Certbot)
├── docker-compose.blue.yml    # Blue 앱 인스턴스 (backend, ai, worker, web)
├── docker-compose.green.yml   # Green 앱 인스턴스
└── nginx/
    ├── nginx.conf
    ├── upstream-blue.conf
    ├── upstream-green.conf
    └── upstream-active.conf   # 현재 활성 색상 복사본
```

### 4.3 Blue/Green 배포 절차

GitLab CI 파이프라인에서 자동 실행되며, 수동 실행 시:

```bash
ssh ubuntu@<EC2_IP>
cd /opt/folio
bash infra/scripts/deploy.sh <IMAGE_TAG>
```

흐름:
1. `/opt/folio/active-color` 읽기 → 반대 색상 결정
2. Doppler에서 prd 시크릿 → `.env` 다운로드
3. 비활성 색상 이미지 pull → 컨테이너 기동
4. 헬스체크 (`/actuator/health`, `/v1/health`, `/healthz`) — 실패 시 자동 롤백
5. Nginx upstream 전환 + reload
6. 5초 안정화 후 이전 색상 컨테이너 종료
7. `active-color` 업데이트 + `.env` 삭제 + 미사용 이미지 정리

### 4.4 Nginx 라우팅

```
https://<domain>/             → React 웹 빌드 (SPA)
https://<domain>/api/*        → Spring Boot backend
https://<domain>/sync/*       → PowerSync (WebSocket)
http://<domain>/.well-known/acme-challenge/ → certbot
```

### 4.5 SSL 인증서

- Let's Encrypt + Certbot
- 인증서 경로: `/opt/folio/data/certbot/conf/live/<domain>/`
- 자동 갱신: certbot 컨테이너가 12시간 주기로 `certbot renew`

### 4.6 백업

- cron: `0 3 * * *` (매일 새벽 3시)
- PostgreSQL: `pg_dump` → gzip → S3 (`daily/`, `weekly/`, `monthly/`)
- MongoDB: `mongodump` → gzip → S3
- 보존: 일일 7일 / 주간 4주 / 월간 3개월

## 5. 배포 시 특이사항

1. **Vite 빌드 환경변수는 이미지에 박힘** — `Dockerfile.web` 빌드 시 `--build-arg VITE_*` 로 주입되므로 환경별로 다른 이미지가 만들어진다.
2. **PostgreSQL `wal_level=logical`** 필수 — PowerSync가 logical replication을 사용한다. `SHOW wal_level;` 로 확인.
3. **MongoDB Replica Set** — PowerSync는 mongo replica set만 지원. 단일 노드여도 `rs.initiate()` 필요.
4. **Electron은 런타임에 Doppler 접근 불가** — 사용자 PC에서 실행되므로 빌드 시점에만 `VITE_*` 변수가 번들에 포함된다.
5. **Refresh Token은 Redis** — DB가 아닌 `RT:{writer_id}:{device_id}` 키로 Redis에 저장된다 (TTL 적용).
6. **GitLab CI에서 `--no-verify` / hooks skip 금지** — Doppler service token (`DOPPLER_TOKEN_PRD`)이 누락되면 배포 실패.
7. **Blue/Green 전환 중 5초 대기** — Nginx reload 후 연결 드레인 시간 필요.
