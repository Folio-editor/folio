# Folio - 서비스 명세서

## 1. 서비스 정의

Folio는 스토리 작가, 소설가를 위한 원고 편집 서비스이다.
웹사이트와 데스크탑 앱 두 가지 플랫폼으로 제공된다.

### 대상 사용자
- 웹소설 작가
- 소설가
- 시나리오 작가
- 기타 장편 콘텐츠 창작자

### 핵심 가치
- 오프라인 환경에서도 완전한 원고 작성 및 편집
- 체계적인 작품 구조 관리 (프로젝트 > 챕터 > 장면)
- 클라우드 동기화를 통한 다중 기기 지원

### 플랫폼 구분

| 구분 | 웹사이트 | 데스크탑 앱 |
|------|----------|-------------|
| 기술 | React (공유 코드베이스) | Electron + React |
| 주요 역할 | 원고 편집 (데스크탑과 동일) | 원고 편집 IDE |
| 데이터 | REST API → PostgreSQL (서버 직접) | 로컬 SQLite → PowerSync → PostgreSQL |
| 오프라인 | 불가 | 가능 |
| 개발 순서 | 2순위 (데스크탑 완성 후 확장) | **1순위** |

### 코드 공유 전략

에디터/UI 코드는 양 플랫폼에서 100% 공유하고, 데이터 접근 계층만 분기한다.

```
src/
  shared/           ← 공유 코드 (에디터, UI, 상태 관리, 비즈니스 로직)
  platform/
    electron/        ← IPC → SQLite
    web/             ← fetch → REST API
```

## 2. 웹사이트 기능 명세

웹사이트는 두 가지 영역으로 구분된다.

### 2.1 랜딩/온보딩 (비로그인 영역)

서비스 홍보 및 데스크탑 앱 설치를 유도하는 공개 페이지.

- 서비스 소개 및 주요 기능 홍보
- 데스크탑 앱 다운로드 (OS별 설치 파일 제공: Windows, macOS)
- 설치 가이드 / 시작하기 안내
- 요금제 / FAQ 등 정보 페이지

### 2.2 웹 에디터 (로그인 영역)

로그인 후 접근 가능한 원고 편집 환경. 데스크탑 앱과 동일한 기능.

#### 2.2.1 인증
- Google OAuth 2.0 소셜 로그인 (브라우저 리다이렉트 방식)
- JWT 토큰을 브라우저 저장소에 보관
- 온라인 필수 (오프라인 미지원)

#### 2.2.2 기능 범위
- 데스크탑 앱과 동일한 원고 편집 기능 (TipTap 에디터 공유)
- 데이터는 REST API를 통해 서버 PostgreSQL에 직접 읽기/쓰기
- 동기화 로직 불필요 (서버 DB가 곧 원본)

## 3. 데스크탑 앱 기능 명세

### 3.1 인증

#### 3.1.1 소셜 로그인 (OAuth 2.0)
- Google OAuth 2.0을 통한 소셜 로그인
- Electron 앱에서 시스템 브라우저를 열어 Google 로그인 → 인증 완료 후 앱으로 콜백
- 로그인 성공 시 Spring 백엔드에서 JWT 토큰 발급
  - Access Token: 수명 짧음 (API 인증용)
  - Refresh Token: 수명 긺 (Access Token 재발급용)
- 토큰은 OS 자격증명 저장소(keytar)에 안전하게 보관

#### 3.1.2 인증 상태
- 앱 실행 시 저장된 토큰으로 자동 로그인 시도
- Access Token 만료 시 Refresh Token으로 자동 갱신
- 오프라인 상태에서도 로컬 기능은 정상 사용 (인증 없이 원고 작성 가능)
- 로그아웃 시 서버에서 Refresh Token 삭제 + 클라이언트 토큰 삭제, 로컬 데이터는 유지

#### 3.1.3 회원 탈퇴
- 소프트 삭제 (deleted_at 처리)
- 개인정보 마스킹 또는 파기
- 탈퇴 후 로컬 데이터 삭제 여부 사용자 선택

#### 3.1.4 권한 관리
| 권한 | 설명 |
|------|------|
| user | 일반 사용자 (기본) |
| premium | 프리미엄 사용자 (구독/결제) |
| admin | 관리자 |

#### 3.1.5 소셜 로그인 후보
| 제공자 | 우선순위 | 비고 |
|--------|----------|------|
| Google | 1순위 | MVP 단계에서 구현 |
| (추후 확장 가능) | - | Apple, 카카오, 네이버 등 |

### 3.2 워크스페이스 (작품 관리)

사용자는 작품 단위로 워크스페이스를 생성하여 작업 환경을 분리한다.
하나의 워크스페이스 = 하나의 작품.

#### 3.2.1 워크스페이스 생성
- 작품명(소설 제목)을 입력하여 새 워크스페이스 생성
- 생성 시 입력 항목:
  - 작품명 (필수)
  - 작가명 (선택, 기본값: 계정 이름)
  - 작품 설명/시놉시스 (선택)
- 장르는 워크스페이스 진입 후 기획 영역에서 설정

#### 3.2.2 워크스페이스 목록
- 앱 실행 시 워크스페이스 목록 화면 표시
- 최근 작업한 워크스페이스 우선 정렬
- 워크스페이스별 마지막 수정일, 총 글자수 등 요약 정보 표시

#### 3.2.3 워크스페이스 관리
- 작품 정보 수정 (작품명, 설명 등)
- 워크스페이스 삭제 (확인 팝업 → `status='trashed'`로 변경, 목록에서 숨김)
- 휴지통에서 복구 가능, 30일 후 배치 작업으로 영구 삭제 (CASCADE)
- 워크스페이스 전환 (목록에서 선택하여 진입)

#### 3.2.4 워크스페이스 내부 구성

워크스페이스 진입 시 아래 7개 영역으로 구성된다. 각 영역은 텍스트 데이터 기반으로 작업한다.

| 영역 | 설명 |
|------|------|
| 기획 | 작품의 슬로건, 장르, 타겟 독자, 분위기 등 방향성 정리 |
| 세계관 | 작품의 배경, 시대, 지역, 규칙, 설정 등 세계관 자료 |
| 등장인물 | 캐릭터 프로필, 관계, 성격, 외형 등 인물 자료 |
| 플롯 | 줄거리 구조, 회차별 전개 설계, 스토리라인 흐름 계획 |
| 원고 | 실제 본문 집필. 독자에게 보여줄 완성 원고 |
| 복선 | 복선 설정/회수 추적, 상태 관리 (미회수/회수완료/폐기) |
| 아이디어 아카이브 | 즉각적으로 떠오른 영감, 좋은 문장, 표현 등을 저장하고 필요 시 활용 |

### 3.3 기획

작품의 방향성과 정체성을 정의하는 영역. 상단 정형 폼 + 하단 자유 에디터 혼합 구성.

#### 정형 입력 필드
| 필드 | 입력 형태 | 설명 |
|------|-----------|------|
| 슬로건 | 텍스트 (1줄) | 작품의 핵심 가치와 메시지를 한 문장으로 정의 |
| 장르 | 태그 (복수 선택) | 판타지, 로맨스, 미스터리, SF, 무협, 호러 등 |
| 분위기 | 태그 (복수 선택) | 진지, 유머, 다크, 감성, 긴장감, 잔잔함 등 |
| 타겟 | 텍스트 (1줄) | 주요 독자층 |

#### 자유 에디터 영역
- 시놉시스, 레퍼런스 작품, 연재 계획 등 자유롭게 작성
- TipTap 리치 텍스트 에디터 사용

### 3.4 세계관

중첩 가능한 노트 목록 구조. 노트 안에 하위 노트를 추가하여 트리 형태로 확장 가능.

#### 기본 템플릿 (워크스페이스 생성 시 앱 로직으로 자동 생성, 사용자 자유 편집/삭제 가능)
- 시대/배경
- 공간/지리
- 세력/조직
- 규칙/법칙
- 역사/연표

#### 노트 구조
- 각 노트는 TipTap 리치 텍스트 에디터로 작성
- 노트 내부에 하위 노트를 추가하여 계층 구조 형성 가능
- 기본 템플릿 노트도 이름 변경/삭제/순서 변경 자유
- 사용자가 원하는 노트를 무제한 추가 가능

#### 구조 예시
```
세계관/
  ├─ 시대/배경
  ├─ 공간/지리
  │    ├─ 아르카디아 대륙
  │    ├─ 북방 설원
  │    └─ 해저 도시
  ├─ 세력/조직
  │    ├─ 제국
  │    └─ 용병단
  ├─ 규칙/법칙
  │    └─ 마법 체계
  ├─ 역사/연표
  └─ (사용자 추가 노트)
```

### 3.5 등장인물

인물 카드 목록 + 소속 태그 + 필터 기반 구성.

#### 인물 카드 필드

**기본 필드:**
| 필드 | 입력 형태 | 필수 | 설명 |
|------|-----------|------|------|
| 이름 | 텍스트 | 필수 | 캐릭터 이름 |
| 프로필 이미지 | 이미지 업로드 | 선택 | 캐릭터 초상 |
| 성별 | 선택 | 필수 | 남 / 여 / 기타 / 미설정 |
| 나이 | 텍스트 | 필수 | "25세", "불명", "수백 년" 등 자유 입력 |
| 외형 | 텍스트 | 필수 | "흑발 적안", "왼팔에 흉터" 등 |
| 성격(MBTI) | 선택 + 텍스트 | 필수 | MBTI 선택 + 성격 보충 설명 |
| 세계관 태그 | 태그 (복수) | 선택 | 세력/조직, 공간/지리 등 세계관 노트 통합 연동 |

**커스텀 필드:**
- 사용자가 원하는 필드를 자유롭게 추가 (필드명 + 값)
- 예시: 특기, 약점, 좌우명, 취미 등

**자유 노트:**
- TipTap 에디터로 과거사, 목표, 성장 아크 등 자유 서술

#### 목록 화면
- 인물을 카드 형태로 나열
- 카드에 이름, 역할, 소속 태그 표시
- 소속 필터로 특정 세력/조직에 속한 인물만 필터링
- 소속 태그는 세계관 > 세력/조직 노트와 연동 (DB 다대다 관계)

#### 세계관 태그 연동 규칙
- 태그 목록은 세계관 노트(세력/조직, 공간/지리 등)에서 자동 참조
- 통합 태그 시스템: 중간 테이블 1개로 어떤 세계관 노트든 태그로 연결
- 세계관 노트 이름 변경 시 인물 카드의 태그에 자동 반영
- 세계관 노트 삭제 시 해당 태그 제거 (인물은 유지)
- 필터에서 태그 카테고리(세력, 지역 등)별 구분 가능

#### 관계도 (추후 구현)
- MVP 이후 인물 간 관계를 시각적 노드 그래프로 표시하는 기능 추가 예정

### 3.6 플롯

줄거리 설계 영역. 세계관과 동일한 중첩 노트 구조에 플롯 전용 요소를 추가.

#### 노트 구조
- 중첩 노트 목록 (막 > 회차 계층 또는 플랫 나열 자유)
- 각 노트는 TipTap 리치 텍스트 에디터로 상세 전개 작성
- 노트 추가/삭제/이름 변경/순서 변경 자유

#### 막(파트) 필드
| 필드 | 입력 형태 | 필수 | 설명 |
|------|-----------|------|------|
| 막 제목 | 텍스트 | 필수 | "1막: 시작", "2막: 전개" 등 |
| 자유 노트 | TipTap 에디터 | 선택 | 막 전체의 방향성, 메모 등 |

#### 회차 필드
| 필드 | 입력 형태 | 필수 | 설명 |
|------|-----------|------|------|
| 제목 | 텍스트 | 필수 | 회차 제목 ("1화: 주인공 각성", "프롤로그" 등 자유 입력) |
| 상태 | 선택 | 필수 | 예정 / 작성중 / 완료 |
| 플롯 내용 | TipTap 에디터 | 선택 | 해당 회차의 줄거리 전개, 사건 흐름, 메모 등 상세 기술 |
| 원고 연결 | 링크 | 선택 | 해당 회차의 원고로 바로 이동 |

#### 구조 예시
```
플롯/
  ├─ 1막: 시작
  │    ├─ 1화: 주인공 각성     [예정]
  │    ├─ 2화: 동료 합류       [작성중]
  │    └─ 3화: 첫 의뢰         [완료]
  ├─ 2막: 전개
  │    ├─ 11화: 적대자 등장    [예정]
  │    └─ 12화: 첫 패배        [예정]
  ├─ 3막: 클라이맥스
  └─ 4막: 결말
```

### 3.7 원고

실제 본문을 집필하는 영역. 플롯과 동일한 중첩 노트 구조(막 > 회차)이나 독립적으로 운영.

#### 플롯과의 관계
- 플롯과 원고는 **각각 독립적으로 생성/관리**
- 플롯 없이 원고만 바로 집필 가능
- 필요 시 회차 간 **1:1 양방향 링크**로 상호 연결
- 플롯에서 설계 → 원고에서 집필, 또는 원고 먼저 → 플롯 역정리 모두 가능

#### 플롯 ↔ 원고 링크 연결 방식

**연결 규칙:**
- 1:1 연결 (플롯 회차 하나 ↔ 원고 회차 하나)
- 연결은 선택사항 (연결 없이도 양쪽 독립 동작)
- 한쪽에서 연결하면 반대쪽에도 링크 자동 표시
- 연결 해제 시 링크만 제거, 양쪽 데이터 유지

**사용 흐름별 UI:**

| 상황 | 버튼 | 동작 |
|------|------|------|
| 플롯 있고 원고 없음 | `[원고 작성하기]` | 원고에 회차 자동 생성 + 링크 연결 + 원고 에디터로 이동 |
| 원고 있고 플롯 없음 | `[플롯 생성하기]` | 플롯에 회차 자동 생성 + 링크 연결 + 플롯 에디터로 이동 |
| 양쪽 다 있고 미연결 | `[플롯 연결]` / `[원고 연결]` | 상대측 회차 목록에서 검색/선택하여 연결 |
| 이미 연결됨 | `[플롯 보기]` / `[원고 보기]` | 연결된 회차로 바로 이동 |
| 연결 해제 | `[연결 해제]` | 링크만 제거, 양쪽 데이터 유지 |

#### 회차 필드
| 필드 | 입력 형태 | 필수 | 설명 |
|------|-----------|------|------|
| 제목 | 텍스트 | 필수 | 회차 제목 ("1화: 각성", "번외편" 등 자유 입력) |
| 상태 | 선택 | 필수 | 미작성 / 초고 / 퇴고 / 완성 |
| 본문 | TipTap 에디터 (풀) | 필수 | 실제 원고 본문 |
| 글자수 | 자동 계산 | 자동 | 본문 작성 시 실시간 집계 |
| 플롯 연결 | 링크 | 선택 | 해당 회차의 플롯으로 바로 이동 |

#### 원고 삭제 (휴지통)
- 회차 삭제 시 `status='trashed'`로 변경, 목록에서 숨김
- 휴지통에서 복구 가능, 30일 후 배치 작업으로 영구 삭제 (CASCADE)
- 하위 데이터(PlotEpisodeLink, ForeshadowLink 등)는 행이 유지되므로 함께 보존

#### 노트 구조 (세계관/플롯과 동일)
모든 노트는 동일한 테이블에 `parent_id`로 계층을 표현한다.
- `parent_id`가 NULL → 최상위 노트 (막 또는 회차)
- `parent_id`가 있음 → 해당 노트의 하위 (회차)
- "막"은 별도 타입이 아니라, 하위 노트를 가진 노트가 곧 막 역할

이 구조로 막을 쓰는 작가와 안 쓰는 작가 모두 동일한 DB 구조에서 동작한다.

#### 구조 예시

**막 사용 시:**
```
원고/
  ├─ 1막: 시작                          (parent_id: NULL)
  │    ├─ 1화: 주인공 각성  3,200자 [초고]  (parent_id: 1막)
  │    ├─ 2화: 동료 합류    2,800자 [퇴고]  (parent_id: 1막)
  │    └─ 3화: 첫 의뢰     0자    [미작성] (parent_id: 1막)
  └─ 2막: 전개                          (parent_id: NULL)
```

**막 없이 사용 시:**
```
원고/
  ├─ 1화: 각성       3,200자 [초고]   (parent_id: NULL)
  ├─ 2화: 합류       2,800자 [퇴고]   (parent_id: NULL)
  └─ 3화: 첫 의뢰    0자    [미작성]  (parent_id: NULL)
```

### 3.8 복선

복선의 설정(심기)과 회수를 추적/관리하는 영역.

#### 복선 카드 필드
| 필드 | 입력 형태 | 필수 | 설명 |
|------|-----------|------|------|
| 복선명 | 텍스트 | 필수 | "주인공의 정체", "검은 편지의 발신자" 등 |
| 상태 | 선택 | 필수 | 진행중 / 완결 / 폐기 |
| 중요도 | 선택 | 필수 | 상 / 중 / 하 |
| 설정(심기) | 회차 연결 (복수) | 선택 | 복선을 심은 원고/플롯 회차 연결 |
| 회수 | 회차 연결 (복수) | 선택 | 복선을 회수한 원고/플롯 회차 연결 |
| 메모 | TipTap 에디터 | 선택 | 복선 의도, 회수 계획, 관련 인물 등 |

#### 목록 화면
- 복선을 카드 형태로 나열
- 상태 필터: 전체 / 진행중 / 완결 / 폐기
- 상태별 그룹핑 표시

#### 타임라인 게이지
각 복선 카드에 원고 회차 기준 가로 게이지를 표시하여 심기/회수 시점을 시각화.
복선은 여러 회차에 걸쳐 복수로 심기/회수될 수 있다.

**마커 색상:**
- 🔵 심기 시점 (복수 가능)
- 🟢 부분 회수 시점 (복수 가능)
- 🔴 최종 완결 회수 시점

**상태별 게이지 표시:**

진행중 (부분 회수 중):
```
복선: 주인공의 정체 [진행중] 중요도: 상

1화───10화───20화───30화───40화───50화 (현재)
│            │       │
🔵 심기      🔵 심기  🟢 회수
(3화)       (15화)  (22화)
```

완결:
```
복선: 주인공의 정체 [완결] 중요도: 상

1화───10화───20화───30화───40화───50화
│            │       │       │       │
🔵 심기      🔵 심기  🟢 회수  🟢 회수  🔴 완결
(3화)       (15화)  (22화)  (35화)  (48화)
```

폐기:
```
복선: 버려진 설정 [폐기] — 게이지 전체 흐리게(비활성화) 처리
```

#### 미회수 복선의 시각적 인지
- 게이지는 1화부터 현재 최신 회차까지를 기준으로 비율 표시
- 장기 미회수 복선은 마커가 게이지 앞쪽에 치우쳐 표시되므로 자연스럽게 한눈에 인지 가능
```
복선: 떨어진 목걸이 [진행중]

1화───10화───20화───30화───40화───50화 (현재)
       │
       🔵 심기                (게이지 뒤쪽이 텅 비어있음 → 오래 방치된 복선)
       (7화)
```

#### 역참조
- 원고/플롯 회차를 열면 해당 회차에 연결된 복선 목록이 표시됨
- 집필 중 "이 회차에 어떤 복선이 걸려있는지" 바로 확인 가능

### 3.9 아이디어 아카이브

즉각적으로 떠오른 영감, 좋은 문장, 표현 등을 빠르게 저장하고 필요 시 꺼내 활용하는 공간.

#### 아이디어 카드 필드
| 필드 | 입력 형태 | 필수 | 설명 |
|------|-----------|------|------|
| 내용 | TipTap 에디터 | 필수 | 아이디어 본문 |
| 카테고리 | 태그 (단일 선택) | 선택 | 고정 5개 중 택 1 (선택 안 해도 됨) |
| 생성일 | 자동 | 자동 | 작성 시점 자동 기록 |

#### 고정 카테고리 태그
- 문장 — 좋은 표현, 비유, 묘사
- 장면 — 장면 구상, 연출 아이디어
- 설정 — 세계관, 인물 관련 아이디어
- 반전 — 트위스트, 반전 소재
- 대사 — 인상적인 대사, 명대사 후보

고정 5개 태그만 제공. 사용자 추가 불가.

#### 목록 화면
- 아이디어를 카드 형태로 나열
- 카테고리 태그 필터로 원하는 유형만 필터링
- 최신순 정렬 기본

### 3.11 동기화

로컬 SQLite와 서버 PostgreSQL 간 데이터 동기화. PowerSync Open Edition 기반.

#### 동기화 대상
| 대상 | 동기화 여부 | 비고 |
|------|------------|------|
| 기획 | O | |
| 세계관 | O | |
| 등장인물 | O | 프로필 이미지 포함 |
| 플롯 | O | |
| 원고 | O | |
| 복선 | O | |
| 아이디어 아카이브 | O | |
| 앱 설정 (테마, 폰트 등) | X | 기기별 로컬 설정 유지 |

#### 동기화 시점
| 상황 | 동작 |
|------|------|
| 온라인 상태 | 변경 발생 시 자동 백그라운드 동기화 |
| 오프라인 → 온라인 복귀 | 오프라인 중 변경 사항 자동 일괄 동기화 |
| 수동 동기화 | 사용자가 동기화 버튼으로 즉시 트리거 가능 |

#### 오프라인 동작
- 네트워크 없이도 모든 기능 정상 동작 (로컬 SQLite가 원본)
- 오프라인 중 작성/수정/삭제 모두 가능
- 온라인 복귀 시 변경분 자동 동기화

#### 충돌 해결
- 기본 전략: **last-write-wins** (마지막 수정이 우선)
- 동일 회차를 다른 기기에서 동시 수정한 경우 최종 수정 시간 기준으로 반영
- 1인 사용 시나리오 기준 설계 (동시 편집 빈도 낮음)

#### 동기화 상태 표시
| 상태 | UI 표시 | 설명 |
|------|---------|------|
| 동기화 완료 | 🟢 | 로컬과 서버가 최신 상태 |
| 동기화 중 | 🟡 | 데이터 전송 중 |
| 오프라인 | ⚫ | 네트워크 미연결, 로컬에서만 작업 중 |
| 동기화 오류 | 🔴 | 동기화 실패, 재시도 필요 |

- 앱 상단 또는 하단 상태바에 동기화 아이콘 상시 표시
- 마지막 동기화 시각 표시

#### 다중 기기
- 동일 계정으로 여러 PC에서 로그인 가능
- 각 기기에서 작업한 내용이 서버를 통해 다른 기기로 동기화
- 앱 실행 시 서버와 최신 상태 자동 동기화

### 3.12 AI 기능

AI API(OpenAI, Claude 등)를 활용한 작가 지원 기능. 모든 AI 호출은 Spring 백엔드를 경유하여 처리.

#### AI 호출 구조
```
Electron App → REST API → Spring Boot → AI API (OpenAI/Claude)
                            ├─ 토큰 잔액 확인
                            ├─ 프롬프트 템플릿 적용
                            ├─ AI 호출 및 결과 반환
                            └─ 토큰 차감 + 이력 저장
```

#### 기능 목록
| 기능 | 설명 |
|------|------|
| 설정 충돌 분석 | 원고 내용과 세계관/등장인물 설정 간 모순 검사 |
| 톤 일관성 검사 | 작품 분위기와 원고 톤의 일관성 분석 |
| 문장/표현 제안 | 선택한 문장에 대한 대안 표현 제안 |
| 줄거리 요약 | 회차 또는 전체 원고의 요약 자동 생성 |

#### 과금 모델
- AI 기능 호출 시 사용자 토큰 차감
- 기능별 차감 토큰 수는 서버의 AI 프롬프트 템플릿에서 관리
- 토큰 잔액 부족 시 호출 차단 + 충전 안내

#### 프롬프트 관리
- AI 프롬프트 템플릿은 서버(관리자)에서 관리
- 클라이언트 업데이트 없이 프롬프트 개선 가능
- 사용할 AI 모델, 최대 토큰 수, 차감 비용 등 서버에서 설정

#### 오프라인 동작
- AI 기능은 온라인 필수 (서버 경유)
- 오프라인 시 AI 기능 비활성화, 나머지 기능은 정상 동작
