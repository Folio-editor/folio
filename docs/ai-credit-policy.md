## 2. 기본 규칙 3가지

### 규칙 1 — 1크레딧 = 8원

어디서든 고정입니다. 어떤 상황이든 바뀌지 않습니다.

### 규칙 2 — 기능 사용 시 원가에 30% 마진이 붙어서 차감

**공식:**

```
차감 크레딧 = (API 원가 × 1.3) ÷ 8
```

**예시:**

- 검수 1회 API 원가가 180원이라면
- 180원 × 1.3 = 234원 (우리가 받을 가격)
- 234원 ÷ 8원 = 29.25
- 반올림 → **29크레딧 차감**

유저는 검수 1회에 29크레딧이 빠진다고 느끼고, 우리는 54원 마진을 챙깁니다.

### 규칙 3 — 결제 금액이 클수록 크레딧을 더 많이 준다

싸게 사고 싶으면 많이 결제하세요. 많이 결제할수록 1크레딧 실가가 싸집니다.

## 6. 우리 마진은 어떻게 계산되나

### 핵심: 유저가 크레딧 쓸 때마다 30% 마진 확보

**예시:**

- 유저가 검수 1회 실행
- 우리 API 비용: 180원 (Anthropic에 냄)
- 유저 크레딧 차감: 29크레딧 (232원 가치)
- **우리 마진: 232 - 180 = 52원 (29%)**

29%가 된 이유는 반올림 때문. 29.25를 29로 내림해서 소수점 손실. 정확히는 30% 의도.

### 결제 상품별 "최악 시나리오" 마진

유저가 크레딧을 100% 다 쓰는 경우:

| 결제 | 받은 크레딧 | 우리 API 비용 최대 | 마진 | 마진율 |
| --- | --- | --- | --- | --- |
| 3,000원 | 300 | 1,846원 | 1,154원 | 38% |
| 5,000원 | 550 | 3,385원 | 1,615원 | 32% |
| 10,000원 | 1,200 | 7,385원 | 2,615원 | 26% |
| 9,900원 구독 | 1,300 | 7,995원 | 1,905원 | 19% |

**어떤 경우에도 마진 플러스.**

### 실제 평균 마진은 더 높다

유저가 크레딧을 100% 다 쓰는 경우는 드뭅니다. 안 쓰고 남긴 크레딧은 우리 수익.

**구독 9,900원 / 사용률별 마진:**

| 사용률 | 사용 크레딧 | API 비용 | 마진 | 마진율 |
| --- | --- | --- | --- | --- |
| 100% | 1,300 | 7,995원 | 1,905원 | 19% |
| 80% | 1,040 | 6,396원 | 3,504원 | 35% |
| 60% | 780 | 4,797원 | 5,103원 | 52% |
| 40% | 520 | 3,198원 | 6,702원 | 68% |
| 0% | 0 | 0원 | 9,900원 | 100% |

평균 60% 사용률 가정 → **구독 평균 마진 약 52%.**

## 7. 원가가 바뀌면 어떻게 되나

### 케이스: 검수 원가 180원 → 120원으로 최적화됨

1크레딧 = 8원은 **그대로**.
기능 차감 크레딧만 **재계산**.

**계산:**

- 120원 × 1.3 = 156원
- 156 ÷ 8 = 19.5
- 반올림 → **20크레딧**

### 유저 체감

|  | 최적화 전 | 최적화 후 |
| --- | --- | --- |
| 검수 1회 차감 | 29크레딧 | 20크레딧 |
| 300크레딧으로 검수 가능 | 10회 | 15회 |

**유저는 "검수가 싸졌다"고 느낌. 우리 마진은 여전히 30%.**

### 반대로 원가가 올라가면

API 단가 인상 등으로 원가가 180원 → 200원 되면:

- 200 × 1.3 = 260
- 260 ÷ 8 = 32.5
- 반올림 → **33크레딧**

유저는 "검수가 4크레딧 더 나가네" 느낌. 유저 혼란 가능성 있어서 공지 필요.

## 8. 토큰 기반 실시간 계산 로직

### 왜 실시간 계산이 필요한가

기능별 "고정 크레딧"을 쓰면 원고 길이에 따라 손익이 달라집니다.

- 원고 짧은 검수: 실제 원가 150원인데 29크레딧 차감 → 우리 이득 과다
- 원고 긴 검수: 실제 원가 220원인데 29크레딧 차감 → 우리 손해

**해결: 매번 실제 토큰량으로 계산.**

### 계산 공식

```
API 원가(원) = (입력 토큰 × 입력 단가) + (출력 토큰 × 출력 단가)
차감 크레딧 = ROUND(API 원가 × 1.3 ÷ 8)
```

### 모델별 단가 (1토큰당 원화)

환율 $1 = 1,450원 기준:

| 모델 | 입력 단가 | 출력 단가 |
| --- | --- | --- |
| Haiku 4.5 | 0.00145원 | 0.00725원 |
| Sonnet 4.6 | 0.00435원 | 0.02175원 |
| Opus 4.7 | 0.00725원 | 0.03625원 |
| OpenAI Embedding | 0.0000290원 | - |

**모든 모델의 출력은 입력의 5배 단가.**

### 실제 계산 예시

**케이스 1: Sonnet 검수 (입력 35,927, 출력 1,083)**

- 입력: 35,927 × 0.00435 = 156.28원
- 출력: 1,083 × 0.02175 = 23.55원
- API 원가: **179.83원**
- × 1.3 = 233.78원
- ÷ 8 = 29.22
- **29크레딧 차감**

**케이스 2: Opus 초안 (입력 39,100, 출력 4,000)**

- 입력: 39,100 × 0.00725 = 283.48원
- 출력: 4,000 × 0.03625 = 145.00원
- API 원가: **428.48원**
- × 1.3 = 557.02원
- ÷ 8 = 69.63
- **70크레딧 차감**

**케이스 3: Haiku 설정 추출 (입력 8,830, 출력 119)**

- 입력: 8,830 × 0.00145 = 12.80원
- 출력: 119 × 0.00725 = 0.86원
- API 원가: **13.66원**
- × 1.3 = 17.76원
- ÷ 8 = 2.22
- **2크레딧 차감**

### 구현 코드 (Python 예시)

```python
USD_TO_KRW = 1450

PRICING_USD_PER_1M = {
    "haiku":  {"input": 1,  "output": 5},
    "sonnet": {"input": 3,  "output": 15},
    "opus":   {"input": 5,  "output": 25},
}

MARGIN_RATIO = 1.3    # 30% 마진
CREDIT_VALUE = 8       # 1크레딧 = 8원

def calculate_credits(model: str, input_tokens: int, output_tokens: int) -> dict:
    """토큰 사용량에서 크레딧 차감량까지 계산."""
    pricing = PRICING_USD_PER_1M[model]

    # API 원가 (원화)
    input_cost = input_tokens * pricing["input"] / 1_000_000 * USD_TO_KRW
    output_cost = output_tokens * pricing["output"] / 1_000_000 * USD_TO_KRW
    api_cost = input_cost + output_cost

    # 크레딧 차감량
    charged = api_cost * MARGIN_RATIO
    credits = round(charged / CREDIT_VALUE)

    return {
        "api_cost_krw": api_cost,
        "charged_krw": charged,
        "credits": credits,
    }

# 사용
result = calculate_credits("sonnet", 35927, 1083)
# {
#   'api_cost_krw': 179.83,
#   'charged_krw': 233.78,
#   'credits': 29
# }
```

### 12-1. 크레딧 이월 정책

**질문: 이번 달 안 쓴 크레딧은 다음 달로 넘길까?**

**옵션:**

| 옵션 | 장점 | 단점 |
| --- | --- | --- |
| 전면 이월 허용 | 유저 호감 | 장기 누적 관리 |
| 월말 전부 소멸 | 회계 단순 | 유저 반발 큼 |
| 3개월까지 이월 | 균형 | 규칙 설명 필요 |

**세부 질문:**

- 종량제 크레딧(유저가 직접 구매): 이월? 영구?
- 구독 크레딧(매달 지급): 이월? 당월 소멸?
- 구독 해지 시 남은 크레딧: 즉시 소멸? 30일 유예?

**제안 (확정 전 참고):**

- 종량제 구매 크레딧: **무제한 이월** (돈 주고 산 거니까)
- 구독 지급 크레딧: **3개월 이월** (사용 유인)
- 구독 해지 시: **30일 내 소진 가능**

### 12-2. 원가 변동 시 반영 주기

**질문: 원가 변동 시 크레딧 차감량을 언제 바꿀까?**

**옵션:**

- 즉시 반영 (변경 감지 즉시)
- 주 단위 반영
- 월 단위 반영 (평균치)

### 12-3. 환불 정책

**질문: 크레딧 구매 후 환불 가능?**

**옵션:**

- 미사용분만 환불
- 구매 후 7일 내만 환불
- 환불 불가

### 12-4. 반올림 방식

**질문: 계산 결과가 소수일 때 어떻게 할까?**

예: 29.25크레딧 → 29 or 30?

**옵션:**

- **반올림(ROUND)**: 0.5 이상 올림. 평균적으로 공정. (현재 제안)
- **올림(CEIL)**: 항상 올림. 우리 유리.
- **내림(FLOOR)**: 항상 내림. 유저 유리.
