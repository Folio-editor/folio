# Folio

## 1. Folio가 뭔가요?

**Folio는 웹소설 작가를 위한 AI 집필 에디터입니다.**

한 줄로 말하면: "1화부터 AI와 함께 쌓아가는 웹소설 에디터(IDE)"

작가가 회차를 쌓을수록 AI가 작품을 더 깊이 이해하고, 설정 충돌 검수·초안 생성·설정 추출을 제공합니다. 개발자에게 VS Code가 있듯, 웹소설 작가에게 Folio가 있는 겁니다.

---

## 2. 왜 이걸 만드나요?

### 작가들이 겪는 진짜 문제

웹소설은 보통 100화 이상 연재합니다. 50화, 100화가 넘어가면 작가 본인도 자기가 쓴 내용을 기억하지 못합니다.

**실제로 일어나는 일들:**

- 1화에서 "파란 눈"이라고 쓴 캐릭터를 47화에서 "갈색 눈"으로 씀
- 전 화에서 팔이 부러졌는데 다음 화에서 멀쩡하게 뛰어다님
- 20화에 깔아둔 복선을 80화에서 회수하는 걸 까먹음
- 조선시대 배경인데 현대 용어를 실수로 씀

독자들은 이런 실수를 바로 잡아냅니다. 댓글로 지적당하면 작가 신뢰도가 떨어지고, 독자 이탈로 이어집니다.

### 현재 해결책은?

- 엑셀에 설정집 정리 → 글 쓰다가 매번 열어보는 건 비현실적
- 뮤벨, 메모장, 한글 → 단순 텍스트 편집기. 설정 충돌 잡아주는 기능 없음
- 전문 편집자 → 비용이 비싸고 매 화마다 쓸 수 없음

**어떤 도구도 "작품을 이해하고 설정을 기억해주는" 기능을 제공하지 않습니다.** Folio가 이 빈 자리를 채웁니다.

## 3. Folio는 구체적으로 뭘 해주나요?

### 기능 1: 검수 (핵심 기능)

**"AI가 원고를 읽고 틀린 곳을 짚어줍니다"**

작가가 원고를 쓰고 "검수" 버튼을 누르면, AI가 원고 전체를 읽고 설정집·이전 회차와 비교합니다.

잡아내는 것들:

- **설정 충돌** — "박지훈은 안경을 쓴다"고 썼는데 설정에 안경 없음
- **시간적 모순** — 김우식이 이미 떠난 뒤인데 옆에서 카메라 세팅 중
- **톤 불일치** — 1990년대 배경인데 "카카오톡" 언급
- **맥락 충돌** — 전 화에서 팔 다쳤는데 이번 화에서 멀쩡

실제 검수 결과 예시:

```
⚠️ 설정 충돌 (심각)
위치: "김우식이 옆에서 카메라를 세팅하고 있었다"
문제: 설정상 김우식은 며칠 전에 장비를 세팅해주고 떠난 상태입니다.
      방송 시작 시점에 옆에 없어야 맞습니다.
제안: 박지훈이 혼자 방송을 시작하는 장면으로 수정하세요.

⚠️ 설정 충돌 (경고)
위치: "박지훈은 안경을 고쳐 쓰며"
문제: 캐릭터 설정에 안경 관련 묘사가 없습니다.
제안: 안경이 고정 설정이면 프로필에 추가하거나, 이 장면에서 삭제하세요.
```

### 기능 2: 초안 생성

**"다음 화의 방향만 알려주면 AI가 초안을 써줍니다"**

작가가 "이번 화에서 주인공이 세 번째 방송을 하고, 위기에 빠진 시청자를 돕는다"라고 방향(스토리라인)을 입력하면, AI가 작품 세계관·등장인물·이전 회차를 참고해서 초안을 생성합니다.

특징:

- 작품의 문체와 분위기를 따라감
- 기존 캐릭터의 성격대로 대사를 씀
- 작품 고유 설정(신안, 물방울 후원 등)을 자연스럽게 반영
- 실시간 스트리밍으로 글자가 하나씩 나타남

초안은 그대로 쓰는 게 아니라, 작가가 에디터에서 자유롭게 수정합니다.

### 기능 3: 설정 불러오기

**"원고를 넣으면 AI가 설정집을 자동으로 정리해줍니다"**

두 가지 상황에서 유용합니다:

- **기존 작가:** 새 화를 쓰고 나서 "이번 화에 새 인물이나 설정이 있나?" 확인
- **이전 작품:** 다른 에디터에서 50화 써온 작가가 Folio로 옮길 때, 기존 원고에서 설정을 한 번에 추출

작동 방식: (수정 필요)

1. 작가가 원고를 입력
2. AI가 원고를 읽고 기존 설정집과 비교
3. 새 인물, 새 설정, 기존 인물의 업데이트를 분류해서 제안
4. 작가가 체크박스로 원하는 것만 선택해서 설정집에 추가

```
새로운 인물:
☑ 침묵하는자 — 30대 중반 남성, 극단적 선택 직전 상태

업데이트 제안:
☑ 박지훈 — "예약자 장부를 적기 시작함" 추가

새로운 설정:
☑ 예약제 — 선착순 물방울 500개, 방송당 1명 무료
```

### 기능 4: 에디터 (기본, 무료)

Folio의 기반은 웹소설 전용 에디터입니다.

- 데스크탑 앱 (Electron + React + TipTap)
- **오프라인 우선** — 인터넷 없는 카페에서도 글 쓸 수 있음
- 온라인 복귀 시 자동 동기화 (PowerSync)
- 작품별 설정집 관리 (인물, 세계관, 복선)
- 회차 관리 (저장/완료 분리)

**에디터 자체는 완전 무료입니다.** AI 기능만 크레딧을 씁니다.

## 5. 기술적으로 어떻게 동작하나요?

### 핵심: "작품을 아는 AI"를 만드는 방법

AI(Claude)는 매번 새로 시작합니다. 이전 대화를 기억하지 못합니다. 그래서 매번 "이 작품은 이런 작품이고, 인물은 이렇고, 이전에 이런 일이 있었다"를 알려줘야 합니다.

문제는 100화짜리 작품의 모든 내용을 매번 넣을 수 없다는 것입니다 (토큰 한계). 그래서 두 가지 기술을 조합합니다.

### 방법 1: 벡터 임베딩 + 검색

"비슷한 과거 장면을 찾아주는 기술"

```
작가가 매 화를 쓸 때마다:
  본문을 장면 단위로 쪼갬 (청킹)
  → 각 장면을 숫자 배열로 변환 (임베딩)
  → DB에 저장

초안/검수 할 때:
  이번 화 내용과 비슷한 과거 장면을 검색
  → 상위 12개만 AI에게 전달
```

100화 전체를 넣을 수 없으니, "가장 관련 있는 장면"만 골라서 넣는 겁니다.

### 방법 2: 설정집 전달(MCP활용)

"인물, 세계관 정보를 DB에서 가져와서 AI에게 넣어줌"

```
검수/초안 할 때:
  DB에서 인물 목록, 세계관 목록을 가져옴
  → AI에게 함께 전달
  → AI가 설정과 원고를 비교해서 검수
```

### AI에게 전달되는 입력 (초안/검수 기준)

| 소스 | 내용 | 토큰 |
| --- | --- | --- |
| 작품 메타데이터 | 제목, 장르, 시대, 톤 | ~500 |
| 등장인물 목록 | 이름, 나이, 성격, 배경 | ~2,000 |
| 세계관 설정 목록 | 세계관 규칙, 용어 | ~2,000 |
| 복선/떡밥 | 미회수 복선 목록 | ~1,000 |
| 최근 3화 원문 | 직전 화 전체 텍스트 | ~9,000 |
| 유사 과거 장면 12개 | 벡터 검색 결과 | ~5,000 |
| **합계** |  | **~19,500** |

이렇게 조립된 컨텍스트와 함께 원고(또는 스토리라인)를 AI에게 전달하면, AI가 "작품을 아는 상태"에서 검수하거나 초안을 생성합니다.

### 오프라인 에디터의 동기화

Folio는 오프라인 우선 에디터입니다.

```
작가 PC: 로컬 SQLite에 저장
  → 온라인 되면 → PowerSync로 서버 PostgreSQL과 동기화
  → AI 기능은 온라인에서만 동작
```

인터넷 없어도 글은 쓸 수 있고, 온라인 복귀 시 자동 동기화됩니다.

## 6. 왜 "완결"이 작가에게 가장 중요한가

### 한국 웹소설 매출 구조

| 항목 | 비중 |
| --- | --- |
| **완결작 e-book 판매** | **55.1%** |
| 회차 단위 결제 | 31.8% |
| 광고·IP 라이선싱 등 | 13.1% |

(출처: 문체부·KPIPA 「2024년 웹소설 산업 현황 실태조사」)

**연재 중 회차 결제는 31.8%, 완결 후 e-book 판매가 55.1%.**

즉 작가의 수익은 "얼마나 잘 시작했나"가 아니라 "**완결까지 갔나**"로 결정됩니다. 중간에 휴재하거나 작품을 포기하면 매출의 절반 이상을 잃는 구조입니다.

### Folio가 완결률을 높이는 방식

1. **설정 충돌이 줄어든다** → 작가가 매 회차마다 이전 설정 찾아보는 시간 절약
2. **떡밥 회수가 자동 추적된다** → 미회수 복선이 쌓여 작품이 무너지는 일 방지
3. **시점 관리가 쉬워진다** → 회귀·환생·빙의 같은 복잡한 시간선도 일관성 유지

Folio는 **"작가가 작품을 끝낼 수 있게 도와주는 도구"** 입니다.

### 완결한 웹소설이 만드는 부가가치

웹소설은 K-콘텐츠 IP의 원천입니다. 완결된 작품이 웹툰·드라마·영화·게임으로 확장되면서 작가의 수익도 폭발적으로 늘어납니다.

| 작품 | 원작 매출 변화 |
| --- | --- |
| 재벌집 막내아들 | 드라마 방영 후 원작 매출 **230배 증가** |
| 나 혼자만 레벨업 | 글로벌 142억 회 조회, 게임 79개국 1위 |
| 사내맞선 | 넷플릭스 글로벌 1위 9개국, 웹툰 매출 20배 증가 |
| 중증외상센터 | 넷플릭스 드라마(2025), 웹툰 글로벌 4억 회 조회 |
| 시멘틱 에러 | 2차 창작 활성화로 원작 매출 600% 상승 |

**한 작품이 만드는 부가가치 — 100억에서 수천억 원.**
모든 가치의 출발점은 작가가 작품을 **완결시키는 것** 입니다.

## 7. 시장은 어떤가요?

### 시장 규모

| 구분 | 수치 | 근거 |
| --- | --- | --- |
| TAM (전체 시장) | 20만 명+ | 국내 웹소설 작가 풀 (한국창작스토리작가협회) |
| SAM (접근 가능) | 5만 명 | 전용 에디터 사용 의향 (뮤벨 16만 DL × 활성 20~30%) |
| SOM (1년차 목표) | 1,200명 | 월 +100명 가정, 누적 손익분기 4개월 도달 |

### 경쟁 분석

| 서비스 | 특징 | 한계 |
| --- | --- | --- |
| 뮤벨 | 국내 1위 웹소설 에디터, 16만 DL | 단순 텍스트 편집, AI 없음 |
| 노벨라 | 웹소설 에디터 | 설정 관리 없음 |
| 펜시브 (Pensiv) | 한국 신생 AI 집필 도구 | AI 검수가 단순 리뷰 수준, RAG 인덱싱 없음 |
| Sudowrite | 해외 AI 글쓰기 도구 | 한국어 미지원, 웹소설 특화 아님 |
| ChatGPT/Claude | 범용 AI | 작품 기억 못 함, 매번 처음부터 설명해야 함 |

**"작품을 이해하는 AI 에디터"는 국내에 Folio가 유일합니다.**

## 9. 작가들의 우려와 대응

### "AI가 내 원고를 학습하는 거 아니야?"

Folio는 작가 원고의 외부 LLM 노출 면적을 구조적으로 최소화합니다.

- **전송 면적 최소화** — 작품 본문은 RAG로 관련 부분만 전송. 회차 전문을 일괄 전송하지 않습니다.
- **DB 평문 0** — 모든 원고는 작품별 키로 암호화 저장(HashiCorp Vault Transit). DB에 평문이 남지 않습니다.
- **로그 격리** — SDK 로거를 격리해 외부 LLM 응답이나 원고 본문이 로그에 남지 않습니다.

Anthropic API는 약관상 기본 학습에 사용되지 않으며, Folio는 정식 출시 전 Zero Data Retention 옵션 적용을 협상할 예정입니다.

### "AI가 쓴 글이면 작가가 아닌 거 아니야?"

Folio의 핵심은 초안 생성이 아니라 **검수**입니다. 검수는 작가가 쓴 글을 AI가 검토하는 것이지, AI가 글을 대신 써주는 게 아닙니다. 초안 생성도 있지만 이건 "참고용"이며, 최종 원고는 항상 작가가 직접 수정합니다.

비유하면: 맞춤법 검사기를 쓴다고 작가가 아닌 건 아니듯, 설정 검수 도구를 쓴다고 작가가 아닌 건 아닙니다.

### "기존 에디터에서 옮기기 귀찮은데?"

"설정 불러오기" 기능으로 기존 원고를 붙여넣으면 AI가 자동으로 인물, 세계관, 복선을 추출해서 설정집을 만들어줍니다. 50화 분량을 직접 정리할 필요 없이, AI가 한 번에 정리해줍니다.

### "무료로 쓸 수 있어?"

에디터는 완전 무료입니다. AI 기능도 가입 시 1,000 크레딧을 무료로 체험할 수 있습니다. 크레딧이 없어도 에디터로 글 쓰는 데는 아무 제한이 없습니다.

## 10. 마케팅 포인트

- "1화부터 100화까지, AI가 함께 기억합니다"
- "설정 구멍, AI가 잡아드립니다"
- "웹소설 작가의 든든한 편집자"

### 핵심 메시지 3가지

**1. 완결률이 곧 수익**
"한국 웹소설 매출의 55%는 완결작 e-book 판매. Folio는 작가가 끝까지 갈 수 있게 돕습니다."

**2. 설정 충돌 방지**
"47화에서 캐릭터 눈 색깔 바뀐 거, 독자가 먼저 발견하게 두실 건가요?"

**3. 에디터는 무료**
"돈 안 내고 써보세요. AI가 필요할 때만 크레딧을 쓰면 됩니다."
